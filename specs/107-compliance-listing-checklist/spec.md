## 1. 模块概述

### 1.1 目的

旧壳（Electron-on-鸿蒙）之所以**必须**被替换，第一动因是合规：同型工程被 AppGallery 以 **P0** 驳回，审核原文为
「经检测发现，应用渲染打开网页时，未使用 ArkWeb 组件，不符合应用市场审核标准。」（🔶 规划 §2.1 引 `pi-desktop-hos/docs/工程规划.md:171`）。
本模块保证：**同样的驳回理由不会再次出现**，并把其余上架前置项（许可、标识、命名、隐私、清理）做成**可勾选、可举证**的清单。

### 1.2 解决的问题

| # | 症状（若不处理） | 后果 | 本模块处置 |
|---|---|---|---|
| 1 | 渲染用第三方内核 / 或自绘渲染、或审核看不出用了系统组件 | 被以 **P0** 驳回；材料无法自证 | G1：形态 + 材料口径 + 截图证据 |
| 2 | 应用声明了「可打开任意网页」的入口能力 | 被判定为浏览器类应用（超出申报范围） | G2：入口能力**只**声明桌面入口 |
| 3 | 包内带 Chromium/Electron 件 | 体积与合规双雷（旧壳 HAP 320.3 MB） | G3：产物清单核对（原生件白名单） |
| 4 | 第三方许可缺失 | 补件、退回 | G4：许可清单随包 + 运行时来源与校验值 |
| 5 | 原生库不合规 / 被要求二进制证书 | 卡审核 | G5：ELF 合规口径（无需 `.codesign`，🔶 库实测） |
| 6 | 未对 AI 生成内容做标识 | 合规项缺失 | G6：界面**常驻**标识（含失败态） |
| 7 | 图标/名称/备案名不一致、`versionCode` 未递增 | 直接被拒 | G7：三一致 + 版本递增 + 测试 Key 说明 |
| 8 | 隐私声明链接不可达 | 被拒 | G8：链接经系统浏览器或应用内承载页可达 |
| 9 | 发布物里留着调试资产（调试端口、调试端点） | 安全与合规风险 | G9：逐项清理并在产物内**证明不存在** |
| 10 | 首启出现「内测/测试/预览版」字样 | 被拒 | G10：文案检索 + 首启截图 |
| 11 | 包内含绕过平台签名/可执行内存控制的组件 | **上架红线** | G11：发布物内**不存在**该类组件；PoC 与发布分支物理隔离 |

### 1.3 范围

**做**：G1–G11 逐条落实与**举证材料**；界面内的 AI 标识；包内第三方许可清单（含运行时来源与校验值）；产物核对口径；
版本与命名一致性；隐私声明可达路径；发布物清理清单；绕行组件的隔离纪律。

**不做**（明确排除）：

| 不做 | 依据 |
|---|---|
| 替上游/库产出它们的许可声明（本工程只**归并**并**随包**） | 库契约 §4（库侧清单由库工程产出）；本工程负责「随包 + 可达」 |
| 使用「二进制证书」等**额外**授权路线 | 规划 §10 明确不申请（本工程无自有可执行 ELF） |
| 用「绕过平台代码签名/可执行内存控制」的方案（路线 J′）拿到 JIT | 红线 **G11**（库 `R23`） |
| 在本模块内改业务功能 | 本模块只做**合规面**（配置、文案、材料、清理） |

## 3. 功能需求（RFC 2119）

### 3.1 G1 渲染形态与材料口径

- **FR-107-001** 主界面**必须**由系统提供的网页渲染组件承载**应用自带的本地界面**；**必须不**随包分发第三方浏览器内核（`FR-ARK-009`）。
- **FR-107-002** 复核质疑时**必须**能给出统一材料口径：**「主界面是应用自带的本地界面，由 ArkWeb 组件加载本机服务，非浏览器上网」**，并附**架构支撑要点**（只加载本机服务地址；外链交系统浏览器或应用内承载；无多窗口/无标签页语义）。
- **FR-107-003** G1 的举证**必须**是：渲染链截图（主界面出现）+ 组件使用位置的可核对证据；**必须不**用「功能正常」这类表述充当证据。

### 3.2 G2 无浏览器语义（✅ 现状成立，必须保持）

- **FR-107-004** 应用入口**必须**只声明桌面启动语义；**必须不**声明可打开任意网页的入口能力（**✅ 现状**：`entry/src/main/module.json5:29-38` 只声明 `entity.system.home` + `action.system.home`）。
- **FR-107-005** 任何新增入口能力**必须**先过本清单；**必须不**在包内提供地址栏、标签页或任意网址导航（`FR-ARK-009`）。
- **FR-107-006** 外链**必须**交系统处理或应用内独立承载页（不构成浏览器功能）；**必须不**在主界面窗口内导航到外部站点。
- **FR-107-007** G2 的举证**必须**是配置断言（`skills` 不含可浏览语义）+ 产物内 `module` 声明的核对结果。

### 3.3 G3 包内无第三方浏览器内核

- **FR-107-008** 包内原生件**必须**限定为白名单（Node 运行时的共享库 + 库引导件 + C++ 运行时）；**必须不**含任何浏览器内核组件或另一套网页渲染实现。
- **FR-107-009** G3 的举证**必须**是**安装包内容清单**（文件名 + 压缩方式 + 大小），**必须不**用磁盘目录清单代替产物清单。

### 3.4 G4 第三方许可清单

- **FR-107-010** 包内**必须**含第三方组件许可清单，至少覆盖：运行时的第三方许可、上游助手与界面组件（MIT）、以及**随包二进制来源与校验值**。
- **FR-107-011** 清单**必须**说明每项的**来源**（项目/版本）与**许可类型**；随包二进制**必须**给出**来源与 SHA-256**。
- **FR-107-012** 许可清单**必须**对用户可达（随包文本 + 界面可打开或文档可查）；**必须不**只存在于仓库 README。

### 3.5 G5 ELF 合规

- **FR-107-013** HAP 内原生库**必须**遵循「无需二进制证书 / 无需额外签名段」的口径；若审核要求补充说明，**必须**给出可复现的核对结论。
- **FR-107-014** 本工程**必须不**申请二进制证书类额外授权（不随包分发自有可执行 ELF 的形态下无正当用途）。

### 3.6 G6 AI 生成内容标识

- **FR-107-015** 主界面**必须**常驻「AI 生成内容」标识（灰字即可），**必须不**依赖 Web 页面内元素（避免页面切换/失败时标识消失）。
- **FR-107-016** 标识在**失败态与加载态**下**必须**依然可见（证明它由应用壳层承载，而非页面内容）。
- **FR-107-017** 标识文案**必须**覆盖中文与英文（跟随系统语言），**必须不**只提供一种语言（`FR-ARK-017/059`）。
- **FR-107-018** G6 的举证**必须**是两次不同时刻的截图（可辨认标识）；⚠️ **禁止**用布局转储类工具的输出当证据（本机拿不到结果，库 §D.8 已实测）。

### 3.7 G7 图标 / 命名 / 备案三一致与版本递增

- **FR-107-019** 应用图标、应用名称与备案名称**必须**三一致；**必须**与提交材料中的写法逐字一致。
- **FR-107-020** 每次上架 `versionCode` **必须**严格递增；版本编码规则**必须**记录在案并可复算。
- **FR-107-021** 发布构建**必须**使用发布签名与发布 Profile；**必须不**把调试签名/调试 Profile 当作发布材料。

### 3.8 G8 隐私声明可达

- **FR-107-022** 隐私声明链接**必须**可达（经系统浏览器或应用内承载页）；**必须不**出现「链接存在但打不开」。

### 3.9 G9 PoC 资产清理

- **FR-107-023** 发布构建内**必须不**存在：调试用的远程调试通道、诊断开关、骨架期自检载荷暴露的调试端点、以及任何仅为验证而存在的样例入口。
- **FR-107-024** 清理**必须**在**产物层面**举证（清单/检索 0 命中 + release 构建的启动截图），**必须不**以「代码里注释掉了」作为证据。

### 3.10 G10 无「内测 / 测试 / 预览版」字样

- **FR-107-025** 首启界面与包内**必须**不出现「内测 / 测试版 / 预览版」等字样；**必须**同时检索包内文案资源与首启截图。

### 3.11 G11 不包含绕过平台代码签名 / 可执行内存控制的组件

- **FR-107-026** 发布物内**必须不**包含任何绕过平台代码签名或可执行内存控制的实现（预签名模板、内存映射搬移类绕行等）。
- **FR-107-027** 相关技术验证资产**必须**与发布分支**物理隔离**（不入发布物、不随包、不出现在发布构建的依赖闭包里），并与 G9 同批执行。
- **FR-107-028** 本工程**必须**在 JIT 需求上走**正路**（按包名申请受限权限并写入 Profile），**必须不**用绕行方案替代。

### 3.12 横切：可审计

- **FR-107-029** 每条合规项**必须**有：判据（可观测） + 证据落点（截图/清单/命令） + 现状标记；**必须不**有「无判据的勾选」。
- **FR-107-030** 合规项的证据**必须**可被第三方用同一条命令或同一份截图复现；**必须不**依赖作者的口头说明。

## 4. 关键实体

### 4.1 合规项清单（实体形状）

| 字段 | 语义 | 约束 |
|---|---|---|
| 编号 | `G1`–`G11` | 与规划 §13 一致（**不得**自造编号） |
| 判据 | 可观测的检查项 | 必须写成「能观测到 X」或「X 不存在」 |
| 证据落点 | 截图 / 产物清单 / 配置断言行 / 命令输出 | 必须给出**具体位置** |
| 现状 | ✅ / ⬜ / ⚠️ | ⬜ 不得写成「预期通过」 |
| 责任面 | 本工程 / 库工程 / 上游 / 平台 | 跨工程的项**必须**写明委托方 |

### 4.2 实体表

| 实体 | 关键字段 | 现状 |
|---|---|---|
| AI 生成内容标识 | 文案（三语）、位置（壳层常驻）、可见性条件（含失败态） | ⬜ 未实现（Phase 3） |
| 第三方许可清单 | 组件名、版本、许可、来源 URL/项目、随包二进制 SHA-256 | ⚠️ 库侧清单**尚未产出**（契约 §4 列为库工程交付物）；本工程侧清单 ⬜ 待创建 |
| 运行时来源与校验值 | 版本、平台、SHA-256、验证设备/时间 | ✅ 已有（`runtime.lock.json`；SHA-256 `3019bf5f…51a1`） |
| 发布物清单 | 条目名、大小、压缩方式 | ✅ 已产出实测（2026-10-17）：三个 `.so` 全部 `compress_type = 8（DEFLATE）`；`rawfile`/`resfile` 仍为 `0（STORED，资源条目不随 native 压缩）`；命令与原始输出见 `overall-data-model.md` §6.2、`overall-test-cases.md` §5 |
| 材料口径 | 一句话口径 + 架构支撑要点 | 🔶 已备（`ARCHITECTURE.md` §9） |
| 版本记录 | `versionCode` / `versionName` / 编码规则 | ✅ 现值 `100` / `0.1.0`（规则 `major*10000+minor*100+patch`） |

### 4.3 合规相关的两条**安装/授权**事实（必须写入材料）

| 事实 | 内容 | 材料用途 |
|---|---|---|
| 声明面 ≠ 授权面 | Profile 不含权限项时装机直接失败：`code:9568289 / PermissionName: ohos.permission.READ_PASTEBOARD`；补齐 Profile 后 `install bundle successfully.` | 说明「受限权限按包名申请并写入 Profile」是**刚性前置** |
| ACL 生效后 JIT 可用 | 不带 `--jitless` 启动无崩溃；`wasm.validate=true`；热循环 **6–9 ms / 2e6**（解释器基线约 59 ms/2e6） | 说明受限权限的**用途与必要性**（AI 运行时依赖可执行内存） |
