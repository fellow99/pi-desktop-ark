# overall-spec.md —— Pi Desktop V2 整体规格（技术无关）

> 本文件只写「**要什么**」与「**怎么判定做到了**」，**不含**技术选型、框架名与文件路径（那些在 `TECH.md` / `ARCHITECTURE.md` / `STRUCTURE.md`）。
> 需求关键字按 **RFC 2119**：**必须**（MUST）· **必须不**（MUST NOT）· **应**（SHOULD）· **可以**（MAY）。
> 依据：规划 [`../docs/000-工程规划.md`](../docs/000-工程规划.md) **§3.1 目标 / §8.1 能力对齐矩阵 / §8.4 平台缺口降级**；判据纪律见 [`constitution.md`](constitution.md) A7。
> 编号：功能需求 `FR-ARK-001` 起；非功能需求 `NFR-ARK-001` 起。**编号一经发布不得复用**。
> 证据标记沿用四标记（✅ **实测** / 🔶 **沿用** / ⬜ **待验证** / ⚠️ **冲突**）：本文件绝大多数条目是「**要求**」，标记只加在**有事实来源**的条目上。

## 1. 系统用途与目标用户

| 项 | 内容 |
|---|---|
| 一句话 | 本应用把**本地 AI 编程助手桌面版**完整搬到目标平台上：应用自带运行环境与本地服务，界面由系统组件渲染，**不依赖任何外部浏览器、不随包分发浏览器内核**。 |
| 目标用户 | ① 在目标设备（笔记本/平板形态）上做代码与文件工作的开发者；② 需要**离线/内网**使用 AI 助手、不愿把会话与凭据交给第三方服务的用户；③ 从旧版桌面包迁移过来的现有用户（功能对齐是硬需求）。 |
| 使用形态 | 单窗口、单实例、单用户；应用在前台时全功能；退出即结束（不做后台常驻）。 |
| 不做（非目标） | 不做浏览器（不提供任意网址导航）；不做终端/PTY；不做版本控制集成；不做后台常驻与开机自启；不做自动更新；不维护自己的运行时实现。 |

## 2. 核心能力（用户视角）

对齐旧版（已完成真机验证的桌面壳）的能力矩阵，逐条给出「用户能做什么」：

| # | 用户能力 | 用户可观测的表现 |
|---|---|---|
| 1 | 打开应用就能用 | 启动后出现明确的阶段提示，最终看到助手主界面；**不出现白屏** |
| 2 | 会话管理 | 能新建、切换、重命名、导出会话；重启应用后会话仍在 |
| 3 | 对话与流式回复 | 发消息后回复**逐字/逐段出现**（不是等全部完成才出现） |
| 4 | 工具调用可视化 | 能看到模型调用了什么工具、参数是什么、结果是什么 |
| 5 | 审批交互 | 需要用户确认的动作会弹出确认，允许/拒绝都生效 |
| 6 | 用量与成本 | 能看到上下文用量、token 与成本统计 |
| 7 | 主题与多语言 | 能切换明/暗主题；界面文案跟随系统语言（中文/英文） |
| 8 | 模型配置 | 能填写接口密钥或走登录流程；凭据保存在应用私有目录，不随日志外泄 |
| 9 | 文件读写与列目录 | 能读、写、编辑、列目录（含中文文件名） |
| 10 | 命令执行 | 能在工作目录下执行 shell 命令并看到输出与退出码 |
| 11 | 按内容搜索 / 按名查找 | 不依赖外部搜索二进制，能在工作目录内搜索与查找，且结果里写明扫描范围与上限 |
| 12 | 工作目录选择与授权 | 能选择工作目录；未获系统授权的目录**明确提示未授权**（不假装成功） |
| 13 | 外部链接 | 界面里的第三方链接不会把整个界面导航走，而是交系统处理或应用内承载 |
| 14 | 失败可见与诊断 | 任何一步失败都能在界面上看到可截图的文字；能查看最近的运行日志 |
| 15 | 合规标识 | 界面内常驻「AI 生成内容」标识 |

> 平台不可用项（对照规划 §8.1 的 ❌ 行；🔶 旧版真机实测 + 平台能力清单）：终端/PTY、版本控制/worktree、插件联网安装、用户目录直写（未授权时）、后台常驻/开机自启全部**不可用**，并且必须在界面/文档中**如实说明**（不得静默降级）。

## 3. 功能需求（按域）

### 3.1 A 域：应用启动与就绪

- **FR-ARK-001** 应用启动后**必须**先显示一个可见的、应用自带的启动画面或状态区，**必须不**出现无内容的空白窗口。
- **FR-ARK-002** 启动过程**必须**以阶段文本呈现（至少区分：准备资源、启动本地服务、等待服务就绪、加载界面、失败），阶段文本**必须**随实际阶段更新。
- **FR-ARK-003** 「就绪」的判定**必须**基于**对本地服务的实际请求成功**，**必须不**以「启动动作已发起」作为就绪判据。
- **FR-ARK-004** 就绪等待**应**采用退避/重试；重试次数与间隔**必须**是可见常量（可被测试引用），且**必须**在上限到达后**立刻**转入失败态而不是无限等待。
- **FR-ARK-005** 应用**必须**保证**单实例**语义：再次启动不得产生第二个独立实例（否则会争抢本地服务端口与数据目录）。
- **FR-ARK-006** 本地服务监听端口**必须**随机或**先探测空闲**后使用；**必须不**依赖某个固定端口一定可用。
- **FR-ARK-007** 当所需权限尚未获得时，应用**必须**在首屏可见之后再触发权限申请流程，**必须不**在首屏出现之前阻塞等待用户操作。
- **FR-ARK-008** 应用在**无外网**环境下**必须**能完成启动到「可输入消息」的过程（依赖网络的仅限模型调用）。

### 3.2 B 域：主界面与 Web UI 全功能

- **FR-ARK-009** 主界面**必须**由系统提供的网页渲染组件承载**应用自带的本地界面**；**必须不**随包分发第三方浏览器内核，**必须不**把界面实现为「浏览器上网」形态（无地址栏、无标签页、无任意网址导航）。
- **FR-ARK-010** 主界面**必须**能使用浏览器本地存储能力（会话级 UI 状态），否则首屏**必须**给出明确失败提示而不是空白。
- **FR-ARK-011** 界面**必须**完整提供会话列表、新建、重命名、导出会话的能力。
- **FR-ARK-012** 发送消息后，回复内容**必须**以流式方式逐步呈现；流式过程中界面**必须**保持可交互（可滚动、可中止）。
- **FR-ARK-013** 工具调用**必须**在界面上可视化为可展开/收起的条目，至少包含：工具名、参数、结果或错误。
- **FR-ARK-014** 需要用户审批的动作**必须**呈现确认入口；拒绝后**必须**体现在会话记录中（不得静默继续执行）。
- **FR-ARK-015** 界面**必须**展示上下文用量与成本信息（至少一处可见位置）。
- **FR-ARK-016** 界面**必须**支持明/暗主题切换（跟随系统或手动，两者择一实现即可，但**必须**可见地生效）。
- **FR-ARK-017** 界面**必须**支持中文与英文两种语言；切换语言后静态文案**必须**随之改变，**必须不**残留另一种语言的固定文案（合规/权限说明文案除外）。
- **FR-ARK-018** 应用**必须**在界面内常驻「AI 生成内容」标识（见 §3.9）。
- **FR-ARK-019** 界面**应**在界面内部完成路由（不引起整页刷新导致流式中断）。
- **FR-ARK-020** 当界面加载失败（本地服务不可达/渲染异常）时，**必须**回退到带错误说明与「重启应用」提示的界面，**必须不**停留在空白页。

### 3.3 C 域：持久化

- **FR-ARK-021** 会话记录**必须**持久化到应用私有目录；**必须不**依赖应用进程内存保存会话。
- **FR-ARK-022** 应用被强制结束或系统回收后再次启动，**必须**能看到此前的会话（内容完整到「最后一条已写入的消息」）。
- **FR-ARK-023** 模型凭据（接口密钥、登录令牌）**必须**保存在应用私有目录；**必须不**出现在应用日志、崩溃记录与导出物中。
- **FR-ARK-024** 首次运行**必须**自动创建所需的私有目录与预置配置模板；**必须不**覆盖用户已有的配置文件。
- **FR-ARK-025** 若载荷/资源需要从只读安装位置复制或解包，**必须**有**内容级**幂等判据（内容摘要一致即跳过），**必须不**以「目录已存在」作为幂等判据。

### 3.4 D 域：模型配置

- **FR-ARK-026** 设置中的「模型」页**必须**允许填写接口地址、模型名与密钥；**或**提供登录流程（二者至少其一，且**必须**在**不联网**登出时给出可读错误）。
- **FR-ARK-027** 配置保存后**必须**在**不重启应用**的情况下生效（下一次请求使用新配置）。
- **FR-ARK-028** 请求失败（鉴权失败/网络不可达/超时）**必须**在界面上给出可读原因，**必须不**只显示「失败」。
- **FR-ARK-029** 应用**必须**默认工作于「离线/仅本地源」模式：不得在后台自动安装插件或下载外部二进制；被禁止的行为**必须**以可见提示出现。

### 3.5 E 域：文件与工具

- **FR-ARK-030** 应用**必须**提供读文件、写文件、精确编辑、追加、列目录、删除、移动、复制能力，操作范围限于**已授权的工作目录**与应用私有目录。
- **FR-ARK-031** 文件路径**必须**支持中文与空格；返回的路径**必须**可直接用于后续工具调用。
- **FR-ARK-032** 应用**必须**提供「执行命令」能力：在指定工作目录下运行命令，返回标准输出/标准错误与退出码。
- **FR-ARK-033** 命令执行的结束判定**必须不**依赖子进程退出事件（本平台不可靠 —— 🔶 旧版实测：`exit`/`close` 事件不送达、子进程变僵尸）；**必须**使用**可判定的输出记号**（如唯一的结束标记行）作为完成判据。（⚠️ 本机另有一份「三事件齐全」的实测，两份材料互斥 ⇒ 保守设计不变，见 `overall-plan.md` §7 的 R10）
- **FR-ARK-034** 命令执行**必须**有默认超时，超时**必须**返回可读错误并可被中止。
- **FR-ARK-035** 应用**必须**提供「按内容搜索」与「按名查找」能力，且**必须不**依赖设备上不存在的外部搜索程序。
- **FR-ARK-036** 搜索/查找结果**必须**在输出中写明：扫描的文件数/目录、跳过的规则（例如忽略哪些目录）、单文件大小上限；**必须不**声称与外部程序的行为逐项一致。
- **FR-ARK-037** 应用**必须**允许用户选择工作目录；选择结果**必须**能被助手用作后续工具的工作目录。
- **FR-ARK-038** 当目标目录位于受系统保护的用户目录且尚未授权时，应用**必须**明确提示「未授权，需要到系统设置授权并重启应用」，**必须不**静默失败或伪造成功。
- **FR-ARK-039** 当某个工具在当前平台上不可用（例如终端、版本控制）时，应用**必须**以明确文案说明不可用与原因，**必须不**提供「看起来能用」的替代入口。
- **FR-ARK-040** 应用**必须**支持从剪贴板粘贴文本/图片到对话输入框（在系统授权允许时）。
- **FR-ARK-041** 应用**必须**在私有时限内自清理临时文件（每次启动或退出时清理自己的临时目录即可）。

### 3.6 F 域：宿主能力（选择器 / 外链 / 通知）

- **FR-ARK-042** 主界面内的**应用自有地址**的跳转**应当**在应用内部承载（不把用户丢出应用）。
- **FR-ARK-043** 指向**外部站点**的链接**必须**交给系统浏览器或应用内独立承载页处理；**必须不**在主界面窗口内直接导航到外部站点。
- **FR-ARK-044** 界面发起的新窗口请求**必须**被拦截并按 FR-ARK-042/043 分流；**必须不**产生无内容或不可操作的新窗口。
- **FR-ARK-045** 应用**应当**在需要时提供系统通知（长任务完成/失败）；通知内容**必须**不含凭据与完整会话内容。
- **FR-ARK-046** 应用**应当**在系统权限缺失时提供「跳到应用设置」的入口；**必须不**引导用户做无效操作。
- **FR-ARK-047** 应用**可以**在版本 1 不提供托盘/状态栏扩展；若提供，其行为**必须**与主界面状态一致（不得出现「界面说失败、托盘说成功」）。

### 3.7 G 域：优雅关停

- **FR-ARK-048** 用户关闭窗口或系统请求终止应用时，应用**必须**触发本地服务的关停流程（尽量关闭监听与写入，避免留下半写文件）。
- **FR-ARK-049** 关停本身**必须**有超时上限；超时后**必须**直接结束，**必须不**无限阻塞用户退出。
- **FR-ARK-050** 关停后再次启动应用**必须**能正常启动到就绪（不得因上次残留导致端口/数据目录争用）。

### 3.8 H 域：错误与诊断

- **FR-ARK-051** 应用**必须**维护一个可见状态机（至少：未启动、启动中、就绪、失败），状态**必须**以用户可读文本呈现。
- **FR-ARK-052** 失败态**必须**同时给出：失败阶段、可读原因、下一步动作（重试 / 查看日志 / 重启应用）。
- **FR-ARK-053** 应用**必须**提供诊断入口，能查看**最近一段本地服务日志**（按需截断显示）。
- **FR-ARK-054** 本地服务的未捕获异常**必须**被捕获并写入应用自己的日志（**必须不**让未捕获异常直接终止整个应用进程）。
- **FR-ARK-055** 一旦本地服务已崩溃，应用**必须**把该情形呈现为**终态失败**，并明确提示「请重启应用」；**必须不**实现或暗示「自动恢复/自动重启」。
- **FR-ARK-056** 日志**必须**至少分两路：主界面渲染外的宿主日志，与本地服务自身日志；**必须不**把宿主组件的原生输出与服务日志混在同一份文件里当作唯一证据。
- **FR-ARK-057** 每条失败文案**必须**能被截图取证（**必须不**只存在于日志中）。
- **FR-ARK-058** 应用**必须**在启动与关键阶段把状态写入系统日志（可被外部工具抓取），用于排障。

### 3.9 I 域：合规标识与上架材料

- **FR-ARK-059** 应用**必须**在界面内常驻「AI 生成内容」标识（灰字常驻即可）。
- **FR-ARK-060** 应用**必须**在包内提供第三方组件许可清单（含运行时与其第三方依赖、上游界面与助手组件），并说明来源与校验值。
- **FR-ARK-061** 应用**必须不**声明浏览器语义（不得声明「可打开任意网页」的入口能力）。
- **FR-ARK-062** 应用首启界面**必须不**出现「内测 / 测试 / 预览版」等字样。
- **FR-ARK-063** 应用图标、应用名称与备案名称**必须**三一致；每次上架 `versionCode` **必须**递增。
- **FR-ARK-064** 隐私声明链接**必须**可达（经系统浏览器或应用内承载页）。

## 4. 非功能需求

| # | 项 | 要求（可验证） |
|---|---|---|
| **NFR-ARK-001** | 首启时长 | 冷启动到「可输入消息」**应** ≤ 15 s（与旧版同量级）；若走需要解包的载荷形态，**必须**有阶段文本与进度可见 |
| **NFR-ARK-002** | 二次启动时长 | 已就绪资源存在时，冷启动到就绪**应**显著快于首启（幂等跳过） |
| **NFR-ARK-003** | 包体 | 签名安装包**应** ≤ 140 MB；**必须不**含任何第三方浏览器内核（对照旧版 320.3 MB） |
| **NFR-ARK-004** | 内存 | 应用稳定运行（空闲 + 一次流式对话）**应**不触发系统内存回收导致的界面重载 |
| **NFR-ARK-005** | 可观测性 | 关键阶段**必须**有系统日志 + 界面文本双通道；日志读取**必须**有「读回」通道（不能只写不读） |
| **NFR-ARK-006** | 离线可用 | 除模型接口调用外，全部功能在无外网环境下可用（FR-ARK-008/029） |
| **NFR-ARK-007** | 国际化 | 静态界面文案**必须**覆盖中文/英文；权限说明文案**必须**与系统语言一致 |
| **NFR-ARK-008** | 可访问性 | 文本控件**必须**可聚焦/可读；关键按钮**必须**有可辨识文本（不只用颜色表达状态） |
| **NFR-ARK-009** | 稳定性 | 端口被占用、目录未授权、服务启动失败**必须**表现为可读失败态，**必须不**表现为应用进程消失（无提示崩溃） |
| **NFR-ARK-010** | 性能基线 | 运行时性能**必须**维持 JIT 档位（WASM 可用；✅ 基线已达成：`wasm.validate=true`、热循环 6–9 ms/2e6）；性能回归判据以既有基线为准（见 `overall-test-cases.md` §5） |
| **NFR-ARK-011** | 数据安全 | 凭据与会话仅存应用私有目录；日志与崩溃记录**必须不**包含密钥明文 |
| **NFR-ARK-012** | 权限最小化 | 权限声明**必须**与功能一一对应；新增权限**必须**同步更新许可/隐私材料与 Profile 授权 |

## 5. 系统边界

| 边界 | 说明 |
|---|---|
| 输入 | 用户键盘/触控/剪贴板；工作目录内的文件；系统授权结果；模型接口返回 |
| 输出 | 界面呈现；应用私有目录写入（会话、配置、日志、缓存）；系统通知（如启用）；系统浏览器跳转 |
| 依赖（外部） | 模型服务接口（可配置，可离线禁用）；系统权限与授权状态；系统提供的网页渲染与网络能力 |
| 不承担 | 不承担任意网页浏览、不承担外部程序管理、不承担后台常驻服务、不承担版本控制、不承担多用户隔离 |
| 数据归属 | 全部会话与凭据属于本机用户；除用户显式配置的模型接口外，**不得**有其它出网请求 |
| 生命周期 | 前台运行；最小化/后台由系统决定；退出即结束；**不支持**在应用内重启本地服务 |
