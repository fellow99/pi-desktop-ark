# spec.md —— `105-auth-loopback-and-cookie` 鉴权（loopback 免密与 Cookie 注入）

> 一句话：让渲染组件**无交互**地进入本地服务页并使 `/api/*` 可用，同时把暴露面压到最小 ——
> **首选**「只监听 loopback + 不设密码」；**回退**「绑局域网 + 随机强密码 + 会话 cookie 注入」。
> 依据：规划 [`../../docs/000-工程规划.md`](../../docs/000-工程规划.md) **§6**（全部，含上游源码事实）、**§5 第 4 条**、**§12 的 R3**、**§2.4**（平台事实）。
> 上游源码事实（**逐行核实，本模块的两条设计结论就建立在这三条上**）：
> ① `pi-web/lib/web-auth.ts:15-19`：`isWebPasswordEnabled()` = 密码环境变量非空 ⇒ **未设密码则认证整体关闭**；
> ② `pi-web/lib/request-security.ts:90-102`：`isApiRequestHostAllowed()` 对 **loopback 主机名/IP 字面量直接放行** ⇒ 同源请求天然通过，**不需要头改写**；
> ③ `pi-web/proxy.ts:42-47`（未启用密码时过 Host 围栏即放行）与 `:50-70`（启用密码后**会话 cookie 优先**，对**包括 `/api/*` 在内**的所有请求生效；Basic 头只是**额外**一条路径）。
> 宪法：[`../constitution.md`](../constitution.md)（A1/A2/A4/A6/A7/A10 · T5/T8/T9）。
> **现状口径**：⬜ **本模块整体未落地** —— 环境装配的**路线分支已经存在**（并行落地的 Node 侧载荷 `payload/env.js:120-169`：`route='loopback'` 只监听回环 + 不设密码；`route='lan'` 缺密码时**显式抛错**、主机名取局域网地址、端口 `0` 交 Node 随机），
> 但**密码生成、会话凭据派生、令牌文件、渲染侧 Cookie 注入、凭据卫生检索**全部**尚未实现**；骨架期的自检载荷不鉴权（`rawfile/selfcheck.js` 只答 `/facts`、`/log`）。
> 证据标记：✅ 实测 / 🔶 沿用 / ⬜ 待验证 / ⚠️ 冲突或风险。

## 1. 模块概述

### 1.1 目的

主界面是**由本地服务渲染的页面**，因此「页面能不能打开、接口能不能调」在鉴权上是一件事：**渲染组件必须被服务端认成合法访问者**。
本模块定义这件事的**两条路线**与它们各自的**失败判据**，并保证：

1. 首屏**不出现登录页**（否则用户被卡在服务自带的登录界面，与应用形态不符）；
2. 攻击面**尽可能小**：首选路线下服务只对**本机**可见；
3. 暴露到局域网时（回退路线）**必须**有强密码与凭据注入，且凭据**不得**泄漏到日志/崩溃记录/导出物。

### 1.2 解决的问题

| # | 症状 | 后果 | 本模块处置 |
|---|---|---|---|
| 1 | 服务启用密码而渲染侧没有凭据 | 首屏被重定向到登录页（用户以为应用坏了） | 路线 ① 免密；路线 ② cookie 注入 |
| 2 | 服务绑 `0.0.0.0` 且无密码 | 同局域网任何设备可访问本机助手与接口 | 默认**只绑 loopback**（路线 ① 唯一形态） |
| 3 | 为「省事」给 `/api/*` 改请求头绕过认证 | 违反宪法 A1，且对**页面导航**无效（页面只认 cookie，✅ `proxy.ts:50-70`） | 明确禁止头改写；首屏只靠 cookie 或免密 |
| 4 | 固定密码 / 调试密码变量 | 凭据进环境变量、日志、崩溃记录（不可上架） | 每启随机生成 + 凭据卫生约束 |
| 5 | 系统代理拦截本机请求 | 「访问本机服务」走代理而失败 | 代理绕过变量必须显式追加本机地址 |

### 1.3 范围

**做**：两条路线的**选型与判据**；服务监听范围与访问凭据的**装配规则**；会话凭据的**派生与注入链路**；代理绕过；凭据卫生。

**不做**（明确排除）：

| 不做 | 归谁 / 依据 |
|---|---|
| 在宿主（壳）里做**业务鉴权** | 宪法 A2（鉴权令牌派生在 Node 侧，壳只注入） |
| 改上游源码、加 preload 桥、引入任何 IPC 载体 | 宪法 A1/A4；规划 §6.2 末句（两条路线都不改上游） |
| 端口随机化与端口回传通道 | `101`（宪法 A8；本模块**只消费**实际端口） |
| ArkWeb 组件配置、导航围栏、清历史 | `103` |
| 登录流程 / 账号体系 / 多用户 | 非目标（规划 §0.3） |
| 固定的调试密码后门 | **禁止**（🔶 旧壳 `PI_DESKTOP_PASSWORD` 会出现在环境变量与日志里） |

## 3. 功能需求（RFC 2119）

### 3.1 路线 ①：loopback 免密（首选）

- **FR-105-001** 默认形态下，本地服务**必须只**监听本机回环地址；**必须不**监听「所有网卡」。
- **FR-105-002** 默认形态下**必须不**设置访问密码 ⇒ 上游据此**整体关闭认证**（✅ `web-auth.ts:15-19`），首屏**必须**直达主界面。
- **FR-105-003** 默认形态下**必须不**把服务暴露到非回环地址：主机名若设置**必须**取回环值，端口**必须不**指定固定值（等价做法是交由服务随机取）；实际监听端口**必须**以服务自身报告的实际值为准（壳**必须不**猜端口；端口机制属 `101`）。
- **FR-105-004** 渲染组件加载的地址**必须**与服务实际监听地址在 **scheme + host + port** 上完全一致，否则「同源」前提不成立（同源是同源请求免头改写的前提，✅ `request-security.ts:90-102`）。
- **FR-105-005** 两条路线下**必须不**改写入站请求头来「补」凭据：同源免密路线不需要；回退路线对**页面导航**也无效（页面只认 cookie，✅ `proxy.ts:50-70`）。

### 3.2 路线 ②：局域网 + 密码 + 会话凭据注入（回退）

- **FR-105-006** 路线 ② **仅当**路线 ① 被**真机证伪**时启用（判据：真机截图不出现主界面首屏）；启用**必须**有可复述的证伪证据，**必须不**因为「保守起见」默认开启。
- **FR-105-007** 路线 ② 下，服务对外暴露时**必须**同时满足：① 访问密码已设置；② 对外主机名**等于本机真实可达的地址**（**必须**从设备网络事实取得，**必须不**硬编码、**必须不**猜）；③ 仅暴露必要端口。
- **FR-105-008** 访问密码**必须**由宿主在**每次启动**时随机生成（长度 ≥ 32 字节等效熵），**必须不**跨启动复用，**必须不**写进日志/崩溃记录/导出物。
- **FR-105-009** 会话凭据**必须**由 **Node 侧**按上游同算法派生（算法要求见 §4.1）；宿主侧**只**负责把它写入渲染组件的 Cookie 存储（分工见宪法 A2）。
- **FR-105-010** 凭据注入**必须**在首屏加载**之前**完成；注入失败**必须**给出可读原因（而不是白屏），并**必须不**把「已注入」当成必然。
- **FR-105-011** 客户端**必须不**绕过上游的认证失败节流：宿主**必须不**以高频重试的方式验证凭据（上游对 Basic 猜测与登录表单**共享**节流，✅ `proxy.ts:50-63`）。

### 3.3 两条路线的共同纪律

- **FR-105-012** **必须不**修改上游源码、**必须不**新增 preload 桥、**必须不**引入任何 IPC 载体承载业务数据或凭据（宪法 A1/A4）。
- **FR-105-013** **必须不**存在「固定调试密码」通道进入发布物（例如由环境变量指定固定密码）；调试可用开关**必须**与 release 构建隔离并列入上架清理清单（G9）。
- **FR-105-014** 代理绕过**必须**显式包含本机回环地址（两条路线）；路线 ② 下**必须**额外包含对外地址。理由：系统代理会让「访问本机服务」走代理而失败。
- **FR-105-015** 凭据**必须不**出现在应用日志、系统日志、崩溃记录与任何导出物中（NFR-ARK-011）。
- **FR-105-016** 就绪探针**必须**使用「在未认证时也稳定可达」的端点，或与真实首屏端点保持同一判据（✅ 上游 `/api/web-auth` 恒定放行：`proxy.ts:69`）；**必须不**用「服务已启动」当就绪判据（`FR-ARK-003`）。
- **FR-105-017** 认证相关的失败（认证被拒 / 注入失败 / 代理拦截）**必须**能与「服务未就绪」区分并各自给出可读原因（`FR-ARK-028/052`）。
- **FR-105-018** 本模块**必须不**改变权限声明面；涉及网络权限的改动**必须**重走 Profile 复验（宪法 A10）。

## 4. 关键实体

### 4.1 会话凭据记录（回退路线）

| 字段 | 语义 | 约束 |
|---|---|---|
| 版本前缀 | 固定 `v1` | 上游校验正则要求（🔶 旧壳镜像上游实现） |
| 过期时刻 | 签发时刻 + 30 天（秒） | 必须 > 当前时刻，否则上游直接判无效 |
| 随机数 | 每次签发随机 | 必须是一次性随机值（不可复用、不可预测） |
| 签名 | 用**访问密码**对「固定前缀 + 版本负载」做 HMAC-SHA256 | 必须与上游同算法同消息构造（本模块不得自创格式） |
| 写入位置 | 渲染组件的 Cookie 存储，作用域 = 服务源 | 作用域必须精确到该源；**必须不**写成通配域 |
| 属性 | 只读（脚本不可读）、宽松同站、有效期 30 天 | 与上游/旧壳口径一致 |

> 规格只写**语义**（含哪些字段、必须满足哪些约束）；**字段名、环境变量名与算法字面量**在 [`plan.md`](plan.md) §4 给出（实现特定）。

### 4.2 两条路线的配置矩阵（语义级）

| 维度 | 路线 ①（首选） | 路线 ②（回退） |
|---|---|---|
| 服务监听范围 | 仅本机回环 | 对外可达（所有网卡） |
| 是否需要访问密码 | **不需要**（认证整体关闭） | 必须（每启随机） |
| 是否需要凭据注入 | 不需要 | 必须（页面导航只认会话凭据） |
| 首屏可达性依赖 | 只需同源地址正确 | 同源地址正确 + 注入成功 |
| 攻击面 | 同机其它应用 | 局域网可达设备（靠随机端口 + 强密码缓解） |
| 启用条件 | 默认 | 路线 ① 真机证伪 |
| 失败后果 | 首屏拿不到服务 ⇒ 失败态 | 出现登录页 ⇒ 视为注入失败 |

## 5. 验收场景（Given / When / Then，逐条可证伪）

| 编号 | Given | When | Then（观测点） |
|---|---|---|---|
| `AC-105-01` | 路线 ① 生效（服务仅监听回环） | 冷启动到就绪 | 首屏截图**没有**登录页；出现主界面（`TC-105-001`） |
| `AC-105-02` | 路线 ① 生效 | 不带任何凭据请求任一 `/api/*` | 返回 **200**（`TC-105-002`；可用 `curl` 复现） |
| `AC-105-03` | 路线 ① 生效 | 在同一台设备上用**非回环**地址访问服务 | **连接失败**（证明未对外暴露）；反之若是「能连上」，则路线选择不成立 |
| `AC-105-04` | 注入路径已实现（路线 ②） | 加载首屏 | 截图**没有**登录页；且 `TC-105-003` 的带凭据请求返回 200 |
| `AC-105-05` | 凭据已签发 | 观察其**形态** | 符合 §4.1（四段、版本前缀、过期在未来、签名段长度固定）；被上游接受（不返回 401、不重定向登录） |
| `AC-105-06` | 连续多次启动 | 观察随机性 | 每次启动密码与凭据**都不同**（不是固定值） |
| `AC-105-07` | 已发生一次认证失败 | 再连续尝试 | 被上游节流拒绝；**不因**壳侧注入而绕过（`TC-105-005`） |
| `AC-105-08` | 排障场景 | 检索应用日志、系统日志、崩溃记录 | **检索不到**密码明文与凭据明文（凭据卫生） |
| `AC-105-09` | 系统配置了代理 | 启动并探活 | 本机请求**不走**代理（探活成功；代理绕过生效） |
| `AC-105-10` | 服务未就绪 | 观察失败信息 | 文案指出「服务未就绪」；**不**与「认证失败」混淆 |

> **禁止的判据**：以「点了一下进得去」判通过；以「日志里出现某一行」判认证生效；以「登录页没报错」判注入成功；
> 用 `uitest dumpLayout` 的返回内容判首屏内容。每条判据**必须**可由第三方用截图 + `curl` 复现（宪法 A7）。

## 6. 非功能需求

| 编号 | 项 | 要求（可验证） |
|---|---|---|
| `NFR-105-001` | 首屏时延 | 免密路线**必须不**引入额外往返（认证关闭 ⇒ 无登录页跳转） |
| `NFR-105-002` | 凭据强度 | 密码 ≥ 32 字节等效熵、每启随机；凭据签名使用 SHA-256 级算法 |
| `NFR-105-003` | 密钥不出界 | 密码与凭据**必须不**出现在日志/崩溃记录/导出物/系统日志（可用检索验证） |
| `NFR-105-004` | 可归因 | 认证失败、注入失败、服务未就绪三类失败**必须**有各自可读文案 |
| `NFR-105-005` | 不改变包形态 | 不新增原生件、不新增权限项、不改上游代码 |
| `NFR-105-006` | 幂等 | 重复注入同一凭据**必须**无副作用；重复启动**必须**生成新凭据并覆盖旧值 |

## 7. 假设与约束

| # | 假设 / 约束 | 影响 |
|---|---|---|
| 1 | 上游在未设密码时**整体关闭认证**（✅ 源码事实） | 路线 ① 成立；若上游升级改变该行为 ⇒ 本模块结论失效（R12 上游漂移） |
| 2 | 同源请求对 loopback 主机名/IP 字面量直接放行（✅ 源码事实） | 不需要头改写；若上游收紧 ⇒ 需重新选型（**不得**用头改写硬顶） |
| 3 | 页面导航（非 API 路径）在启用密码时**只认会话凭据**（✅ `proxy.ts:50-70`） | 回退路线**必须**注入凭据；Basic 头对首屏无效 |
| 4 | 渲染组件访问回环地址的能力**尚未本工程实测**（P0-3） | 路线 ① 的可行性由 `TC-103-002` 首屏截图证伪/证实 |
| 5 | 渲染组件的 Cookie 写入能力**尚未实测** | 路线 ② 若不可用 ⇒ 只能维持路线 ① 或另想办法（另想办法属新决策，须先改规划与本文） |
| 6 | 端口随机化与回传通道属 `101` | 本模块**必须不**自行指定端口 |
| 7 | 上游认证节流不可绕过 | 验证凭据时不得高频重试 |

|---|---|---|
