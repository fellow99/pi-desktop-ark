## 1. 模块概述

### 1.1 目的

用**系统提供的渲染组件**承载应用自带的本地界面，并把「启动 → 就绪 → 渲染 → 失败」四态**全部做可见**：

1. **首屏必有**：应用内加载页（阶段文本 + 进度），**必须不**白屏；
2. **就绪切换**：探活成功后把组件切到本地服务地址（同源、零 CORS、零 IPC 载体）；
3. **历史与返回键**：切换后清历史 + 返回键守卫（否则用户被**永久卡在**加载页）；
4. **导航围栏**：主框架导航到非本源地址必须拦截并分流（外链交系统或应用内承载页），子框架放行；
5. **失败可见**：宿主侧错误视图（阶段 + 原因 + 下一步）+ 诊断面板（日志尾 / 崩溃提示）；
6. **合规正面对上**：只加载本机服务页、不做浏览器语义（无地址栏/无标签页/无任意网址导航）。

### 1.2 解决的问题

| 问题 | 不解决的后果 |
|---|---|
| 没有本地首屏 | 白屏无法诊断（宪法 A5） |
| 存储能力未开 | 🔶 同形态先例：缺 DOM 存储 ⇒ `localStorage = null` ⇒ **SPA 首屏崩** |
| 用非应用内页面当加载页 | 加载页自身可能不可用/不可信；且无法显示应用的真实阶段 |
| 切换后未清历史 | 返回键/手势把用户退回加载页 ⇒ **永久卡在「启动中」** |
| 无导航围栏 | 点外链把整个界面导航走（对话框/异常页面无返回路径）；新窗口请求产生空白窗口 |
| 失败只写日志 | 用户看到「什么都没发生」，无法截图取证 |
| 浏览器语义 | 上架红线（G2：不得声明/呈现「可打开任意网页」） |

| 含 | 不含（归属） |
|---|---|

## 3. 功能需求

### 3.1 渲染组件配置（FR-103-001 ~ FR-103-003）

- **FR-103-001** 主界面**必须**由**系统提供的网页渲染组件**承载**应用自带的本地界面**；**必须不**随包分发第三方浏览器内核，**必须不**呈现浏览器语义（无地址栏、无标签页、无任意网址导航）。
- **FR-103-002** 渲染组件**必须**允许页面执行脚本，**必须**允许页面使用**本地存储**能力（缺失时界面**必须**给出可读失败提示，**必须不**留空白）。
- **FR-103-003** 是否启用**数据库存储**能力**必须**由**对照实测**决定（开/不开各跑一次，记录是否报错），结论**必须**写进文档；**必须不**凭猜测开关。

### 3.2 首屏与就绪切换（FR-103-004 ~ FR-103-006）

- **FR-103-004** 首屏**必须**是**应用内资源页面**；**必须不**使用 `data:` 页面或远程页面作为加载页。
- **FR-103-005** 加载页**必须**显示**阶段文本**（至少区分：准备资源 / 启动本地服务 / 等待服务就绪 / 加载界面），且阶段文本**必须**随真实阶段更新。
- **FR-103-006** 就绪后**必须**把渲染组件切换到**本地服务地址**（loopback + 实际端口）；**必须不**使用固定端口字面量（端口由服务侧回传，见 FR-101-009）。

### 3.3 历史、返回键与围栏（FR-103-007 ~ FR-103-009）

- **FR-103-007** 切换到本地服务页面后**必须**清除浏览历史，**必须**有返回键/手势守卫：按返回**必须不**回到加载页。
- **FR-103-008** **必须**有导航围栏：**主框架**导航到非本源地址**必须**被拦截并按「应用自有地址在应用内承载 / 外部站点交系统或独立承载页」分流；**子框架**请求**必须**放行。
- **FR-103-009** 界面发起的**新窗口请求必须**被拦截并按同一规则分流；**必须不**产生空白或不可操作的新窗口。

### 3.4 失败可见与诊断（FR-103-010 ~ FR-103-012）

- **FR-103-010** 失败时**必须**呈现**宿主侧（非网页）错误视图**，含三要素：**失败阶段 / 可读原因 / 下一步动作**（重试 / 查看日志 / 重启应用）；**必须不**停留在空白页或错误网页。
- **FR-103-011** **必须**提供诊断入口，能展示**日志尾部**（非空）与**崩溃提示**（若存在崩溃记录）；读回失败**必须**显示占位文本而**必须不**抛错。
- **FR-103-012** 「重试」**必须**只重做**可重做**的阶段（重新探活 / 重新投放资源 / 重新加载页面），**必须不**声称或暗示「重启本地服务」；服务已可用时重试**必须不**产生第二个实例。

### 3.5 渲染侧能力与状态呈现（FR-103-013 ~ FR-103-018）

- **FR-103-013** 流式输出（长连接）**必须**在界面上持续推进；**前后台切换/息屏**后的行为**必须**实测并如实记录（可续 / 需重连），**必须不**假设「一定保持」。
- **FR-103-014** 渲染侧关键能力（长连接、Worker、WASM、加密 API）**必须**逐项实测，缺失项**必须**记录并给出**注入兜底方案**；**必须不**以「上游能用」推断本平台能用。
- **FR-103-015** 非安全上下文处置：首选**回环地址**（本机服务）作为可信来源；若被证伪（例如加密 API 不可用）**必须**按回退路线处置（与 **105** 联合定稿），**必须不**用「忽略错误」掩盖。
- **FR-103-016** 状态**必须**以**文本**呈现（不只靠颜色）；界面内**必须**为常驻的「AI 生成内容」标识**留出固定落位**（文案与样式由 107 定稿，本模块保证可见性与不随页面切换消失）。
- **FR-103-017** 渲染进程模型（是否独立进程、前后台行为）**必须**实测并把结论写回架构文档；**必须不**把推断写成事实。
- **FR-103-018** 界面内的**应用自有地址**跳转**应**在应用内部承载（不把用户丢出应用）；外部站点**必须**走系统浏览器或应用内独立承载页。

## 5. 验收场景（Given / When / Then）

- **AC-103-01 本地首屏可见**：Given 冷启动；When 应用刚起来（探活尚未成功）；Then 截图能看到加载页的**标题与阶段文本**（非空白、非错误页）。
- **AC-103-02 渲染组件能访问本机服务**：Given 服务已就绪；When 组件切到本地服务地址；Then 截图出现**界面首屏**，且服务侧日志/端点出现来自渲染进程的请求（**最高优先级**，P0-3）。
- **AC-103-03 本地存储可用**：Given 界面首屏已加载；When 使用会话级界面状态；Then **不出现**「存储为 null」类错误，界面功能可用。
- **AC-103-04 数据库存储对照结论**：Given 关闭该开关跑一次；When 检查界面功能；Then 记录是否报错并把结论写进文档（开/关各一次）。
- **AC-103-05 返回键不回到加载页**：Given 已切到本机服务页面；When 触发返回键/手势；Then **不回到**加载页；**且**主界面仍可用（未退出应用）。
- **AC-103-06 外链围栏**：Given 主界面中有外部站点链接；When 点击；Then 主界面**未被导航走**（同屏文案不变），跳转由系统或独立承载页完成；Given 子框架请求；Then **被放行**（不误伤）。
- **AC-103-07 新窗口拦截**：Given 界面发起新窗口请求；When 触发；Then **不产生**空白/不可操作的新窗口，且按分流规则处理（截图）。
- **AC-103-08 长连接与前后台**：Given 一次流式回复进行中；When 等待 ≥5 min（并做一次前后台切换）；Then 记录连接是否保持/可续，结论写入文档（A5）。
- **AC-103-09 渲染侧能力面**：Given 逐项执行能力探测；Then 每项**有明确结论**（可用/不可用 + 兜底方案），**无**「未测」项。
- **AC-103-10 渲染进程模型结论**：Given 真机观测进程（`aa dump`/系统日志）；Then 给出「独立进程 / 同进程」的可复现结论并写回架构文档（O9）。
- **AC-103-11 宿主侧错误页**：Given 注入一次启动失败（例如目标端点不可达）；When 观察界面；Then 出现**宿主绘制的**错误视图（含阶段 + 原因 + 下一步），**不是**网页错误页，也不是白屏。
- **AC-103-12 重试语义正确**：Given 处于失败态；When 点「重试」；Then 只重做可重做阶段（重新探活/重新加载），日志可见该动作；**不出现**「重启服务」的字样或行为；服务可用时**不产生**第二实例。

## 7. 假设与约束

1. **渲染组件可访问本机回环地址**：🔶 同形态在售先例已证明可行；本工程 ⬜ **必须自测**（P0-3 是 Phase 1 最高优先级）；若被证伪，回退鉴权路线 ②（**105**）。
2. **加载页必须是应用内资源页**（🔶 库 §5.10 第 8 条）；⚠️ 规划 §5 第 12 条另写「**ArkTS 加载页**（ArkWeb 之上叠 ArkTS 视图）」——两者**并存**：加载页用应用内资源页，**错误页与诊断面板**用宿主侧视图（本文件按此口径收敛，见 [`plan.md`](plan.md) §3 决策 1）。
3. **围栏只拦主框架**：子框架（若上游有）不得被误伤；新窗口一律拦截后分流。
4. **不做浏览器**：不提供地址栏、标签页、书签、任意网址导航（合规红线 G2）。
5. **状态不仅靠颜色**：颜色可用于强调，但**必须**有文本（可截图断言）。
6. **日志与崩溃记录的结构**以库契约为准（时间戳 + 流 + 文本；崩溃 = 时间/阶段/信号/提示），本模块只负责**展示**。
7. **同一页面内叠加视图**：不新增路由（路由表固定为单一页面）；如确需新页面**必须**同步改路由表（否则解析失败）。
8. **平台缺口如实说明**：终端/版本控制等不可用项由 106/104 出文案；本模块保证这类提示**有落位**（不隐藏）。
