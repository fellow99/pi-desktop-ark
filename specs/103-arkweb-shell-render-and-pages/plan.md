## 3. 研究结论（关键决策 / 替代方案 / 为何否掉）

| # | 决策 | 替代方案（为何否掉） | 依据 |
|---|---|---|---|
| 1 | **加载页 = 应用内资源页**（现状 `$rawfile('boot.html')`）；**错误页与诊断面板 = 宿主侧 ArkTS 视图** | ① 旧壳的 `data:` loading 页：非应用内资源、不可信、且要 `executeJavaScript` 更新（本形态禁止用 JS 注入传状态，A1）；② 纯 ArkTS 加载页（**规划 §5 第 12 条的字面要求**）：可用但需自绘全部样式与动画，收益低于成本 ⇒ 两者**并存取长**：阶段展示用资源页，失败/诊断用宿主侧视图。⚠️ 该分歧已在 `spec.md` §7.2 记录 | 库 §5.10 第 8 条（**必须**是应用内资源页）、规划 §5 第 12 条、✅ 现状 |
| 2 | `javaScriptAccess(true)` + **`domStorageAccess(true)` 必须开** | 只开脚本：🔶 先例缺 DOM 存储 ⇒ `localStorage = null` ⇒ **SPA 首屏崩**（不可恢复的白屏） | 库 §5.10 第 7 条、规划 §5 第 1 条 |
| 3 | `databaseAccess` **对照实测后定**（开/关各一次） | 直接照抄「必须开」：先例（第三方）**未开**该开关也能在售；凭猜测开关 = 无判据 | `../TECH.md` §6、`TC-103-004` |
| 4 | 就绪切换后**必须** `clearHistory()` + 返回键守卫（`onBackPress`） | 不清历史：返回键/手势退回加载页 ⇒ **永久卡在「启动中」**（库 §5.10 第 8 条点名的坑；⚠️ 现状未实现） | 库 §5.10 第 8 条、规划 §4 时序（「成功则 clearHistory()」） |
| 5 | 围栏用 `onLoadIntercept` + **`isMainFrame()`**：主框架非本源 ⇒ 拦截并分流；子框架 ⇒ 放行 | 只看 URL 不看框架层级：会误伤子框架请求（上游若用 iframe/内嵌预览即坏） | 库 §5.10 第 9 条（等价旧壳 `will-navigate`） |
| 6 | 新窗口请求统一拦截（`onWindowNew`）后按同一规则分流 | 放行新窗口：本形态下会产生空白或不可操作窗口（旧壳实测同类问题：第二窗口不落地）；⚠️ 回调的精确签名须实现时按目标 API 版本的 SDK 定义核对（⬜ 本工程未复核） | 库 §5.10 第 9 条、🔶 旧壳 `main.js:1122-1127` |
| 7 | 外链落点：系统浏览器或应用内独立承载页；⚠️ **不得**照抄旧壳死代码 `ExternalWeb.Open`（未注册、调用即 SIGSEGV） | 在应用内直接打开外部站点：违反 G2（浏览器语义）与 A6；直接调旧壳桥：崩 | 规划 §5 第 8/11 条、🔶 旧壳 `R15`；实现归 **104** |
| 8 | **不需要**「把非安全来源当安全来源」的等价配置：本工程只加载 loopback 本机服务（旧壳需要它是因为绑局域网 + 局域网 IP 页面） | 直接照抄 `unsafely-treat-insecure-origin-as-secure`：无对象可作用，且是额外攻击面；⬜ 但**必须**实测 loopback 下加密 API 是否可用（P0-3/R4） | 规划 §5 第 14 条、`../ARCHITECTURE.md` §4 第 14 行 |
| 9 | 渲染进程模型：先按**独立子进程**预期准备观测手段，⬜ 结论以 `aa dump`/系统日志为准 | 直接断言「同进程」：与已有记录冲突（见「依据」列的间接观测） | ✅ 已有**间接观测**：ACL 证据里出现 `:gpu`/`:render` 子进程名（`docs/ACL配置.md:63`）；`TC-103-010`（O9）仍 ⬜ 待系统化取证 |
| 10 | 视图叠加而非新增路由（加载页/主界面/错误页/诊断面板都在同一页面内切换） | 新增页面：须同步改路由表，且会重建渲染组件实例（丢历史与状态）；本模块 v1 不需要 | `../STRUCTURE.md` §3 |
| 11 | 状态呈现**文本 + 颜色并用**（文本为判据，颜色仅强调） | 只用颜色：违反项目级 `NFR-ARK-008`，且截图不可断言 | 宪法 A7、`pages/Index.ets:81-83`（现状已文本化 ✅） |
| 12 | 长连接与前后台：先按「可能断开」设计（可续/重连提示），⬜ 实测后定稿 | 假设「ArkWeb 后台保持连接」：无证据，且失效表现是「回复停住」最难归因 | 规划 §12 A5、`TC-103-008` |

### 4.5 围栏判定表（目标行为，⬜ 待实现）

| 事件 | 判定 | 决策 | 备注 |
|---|---|---|---|
| 主框架导航到 `http://127.0.0.1:<回传端口>/…` | 本源 | **放行** | 端点来自 101 的端口回传，不得写字面量 |
| 主框架导航到其它协议/主机（`https:`、局域网 IP、`file:` 等） | 非本源 | **拦截** + 分流（外部站点交系统/承载页；应用自有地址应用内承载） | FR-103-008/018 |
| 子框架（`isMainFrame() === false`）请求 | 非主框架 | **放行** | 不误伤内嵌内容 |
| 新窗口请求（`onWindowNew`） | 一律非本源 | **拦截** + 同一分流 | 不产生空白窗口 |
| `about:blank` / `data:` | 非本源 | 拦截（不加载） | 加载页禁止用 `data:` |

**校验规则**：① 放行条件**必须**由「回传端口 + `127.0.0.1`」精确构成（不接受「看起来像本机」的地址，例如 `localhost.`、十进制 IP 变体）；② 端口未回传成功时**不得**放行任何导航（宁严不宽）。

| `webview.WebviewController` | 平台 | `loadUrl` / `clearHistory` / 调试开关 | 部分 ✅ |

### 5.3 事件协议

| 事件 | 触发 | 处理 |
|---|---|---|
| `onControllerAttached` | 渲染组件就绪 | 记日志；**不得**在此同步做长任务 | ✅ `:112-114` |

| `onWindowNew` | 新窗口请求 | 拦截 + 分流 | ⬜ |
| 返回键事件 | 用户返回 | 服务页时不退出/不回退加载页 | ⬜ |
| 诊断刷新 | 「日志」按钮 | 读日志尾并写入 `logTail` | ⬜ |

## 6. 实现策略

### 6.1 架构模式

**状态驱动视图切换**：单一页面持有 `status`/`detail`/`logTail`，渲染组件始终是**同一个实例**（先 `$rawfile`，就绪后 `loadUrl`），宿主侧视图叠加在其上/其下（状态条常驻、诊断区条件渲染）。避免重建组件（重建会丢历史与状态，并可能触发重复加载）。

### 6.2 关键算法

```
aboutToAppear:
  launched 防重入 → flags 解析（AppStorage 回退默认） → status=LAUNCHING；detail=阶段文案
  launch(ctx, flags).then(r => { status = getState(); detail = r;
                                 if (READY) controller.loadUrl(getUrl()) → 成功回调里 clearHistory() })

围栏（Phase 1）:
  onLoadIntercept(e):
     url = e.data.getRequestUrl(); main = e.data.isMainFrame()
     if (!main) return false                      // 子框架放行
     if (isLocalOrigin(url, portFromRuntime)) return false
     intercept: 分流（外部站点 → 交系统/承载页；其它 → 记录日志并阻止）
     return true

新窗口（Phase 1）:
  onWindowNew(e): 记录 url → 分流 → 拦截（不放行任何新窗口）

返回键（Phase 1）:
  onBackPress(): 若当前为服务页 → 消费事件（不退出、不回加载页）；否则交给系统默认
```

### 6.3 错误处理

| 失败面 | 处置 |
|---|---|
| 探活失败/投递失败 | 保持加载页，切换为**宿主侧错误视图**：阶段 + 原因 + 下一步（重试/日志/重启应用） |
| 服务已崩溃（终态） | 文案明确「请重启应用」；**不**提供自动恢复入口（A5/C5） |
| 渲染组件加载失败（网络层） | 显示宿主侧错误视图（不显示网页错误页）；诊断区提示读日志 |
| 日志读回失败 | 显示占位文本（**不抛错**）；面板标注「读取失败原因」 |
| 长连接中断 | 面板/界面给出可读提示，并给出重连动作（⬜ 待 A5 实测后定稿） |

### 6.4 性能

- 加载页为静态资源（无网络依赖），首屏 **≤3 s** 目标（`NFR-103-001`）。
- 组件不重建；状态更新只改 `@State` 文本。
- 诊断面板文本**限制长度**（≤16 KB 或固定行数），避免大文本拖慢界面。
- 围栏判定为纯字符串/端口比对（无 DNS 解析、无外部请求）。
