## 1. 模块概述

### 1.1 目的

应用的结构是「**壳只做四件事**：启动 / 观测 / 宿主能力 / 渲染」（宪法 A2）。本模块就是其中「**宿主能力**」那一件的全部内容：
凡**必须由应用宿主**出面（用户授权、系统选择器、系统浏览器、系统通知、系统日志、系统窗口 API）才能完成的事，
统一以**库冻结的八个能力名**对外暴露，供**本地服务侧（助手进程）**按需调用：

| 冻结能力名（逐字，不得改写） | 面向用户的语义 |
|---|---|
| `runtime.facts` | 宿主侧的运行时事实（服务是否在跑、日志在哪、已注册能力有哪些） |
| `perm.check` | 某个权限当前**是否被授予**（对齐旧壳 `checkPermission`） |
| `perm.openAppInfo` | 打开**本应用的系统设置页**（对齐旧壳 `openApplicationInfoEntry`） |
| `fs.pickFiles` | 用**系统选择器**挑文件，只把**路径**交回 |
| `fs.pickFolder` | 用**系统选择器**挑目录（工作目录），只把**路径**交回 |
| `shell.openExternal` | 把外部站点交给**系统浏览器**（或应用内承载页） |
| `notify.show` | 发一条系统通知（长任务完成 / 失败；v1 按需） |
| `log.hilog` | 把关键信息写进**系统日志**（与宿主日志双通道） |

> 命名来源：库冻结契约 §2.7 与 `ohos-node-bridge/library/src/main/ets/bridge/HostBridge.ets:25-34` 的 `CAPABILITIES`
> 常量（与本表逐字一致 ✅）。**本模块不得新增、改名、缩写任何一条**（见 `FR-104-002`）。

### 1.2 解决的问题

| # | 若不实现会怎样（症状） | 后果 | 本模块处置 |
|---|---|---|---|
| 1 | 助手只能拿到一个写死的工作目录 | 「选择工作目录并授权」能力不成立（`FR-ARK-037`） | `fs.pickFolder` + 工作区主目录清单 |
| 2 | 未授权目录的读写失败被上层当成功 | 用户以为文件保存了（违反宪法 A6「不隐藏平台真相」） | `perm.check` 三态判定 + 「未授权」文案口径（`FR-104-007/008`） |
| 3 | 界面里的第三方链接把主界面**导航走** | 主界面离开本地服务（合规 G1/G2 相邻风险） | `shell.openExternal` + 分流规则（`FR-104-017..021`） |
| 4 | 权限被拒后用户不知去哪里开 | 用户反复点无效按钮 | `perm.openAppInfo`（`FR-104-009`） |
| 5 | 每次启动窗口尺寸/位置回到默认值 | 与旧壳体验不一致（旧壳有 `window-state.json`） | 窗口状态「记忆尺寸」最小版（`FR-104-029`） |
| 6 | 长任务完成/失败无任何提示 | 用户离开界面就永远不知道（v1 按需） | `notify.show`（`FR-104-022`） |
| 7 | 关键信息只写在应用自己的日志文件里 | 排障时外部抓不到（宪法 T8 / A5） | `log.hilog` 双通道（`FR-104-023`） |
| 8 | 选择器把文件**内容**塞进桥 | 大文件走 JSON 载荷 ⇒ 内存与上限问题（库契约 §5.4 参数上限） | 只回传路径；大文件走 copy（`FR-104-013`） |

### 1.3 范围

**做**（本模块交付）：

- 八个能力的**宿主侧实现**（注册进宿主能力桥），含入参/出参规格与结构化错误；
- **工作区主目录清单**（沙箱 / 桌面 / 文档 / 下载四项：绝对路径、存在性、可读性、授权状态）与其对助手的供数口径；
- 导航围栏 / 弹窗拦截中**属于宿主能力的那一半**：外部地址的实际动作（交系统浏览器或应用内承载页）；
- **窗口状态记忆最小版**（尺寸）；
- 通知 / 状态栏（v1 按需，不做托盘）；
- 权限相关的**文案与去向**（未授权 ⇒ 原因 + 「去系统设置」入口）。

**不做**（明确排除，避免与别的模块重叠）：

| 不做 | 归谁 | 依据 |
|---|---|---|
| 加载页 / 错误页 / 诊断面板 / ArkWeb 组件配置 / 清历史 | `103-arkweb-shell` | 宪法 A2；`ARCHITECTURE.md` §4 第 12 行 |
| 导航围栏的**帧/主框架判定**与新窗口事件的接线 | `103`（本模块只提供动作侧） | `overall-test-cases.md` `TC-103-006/007` |
| 端口随机化、状态机、关停编排 | `101` | 宪法 A8；`overall-data-model.md` §2 |
| 用宿主能力桥承载**任何业务数据**（会话、消息、流式内容、进度） | **一票否决** | 宪法 A1；库宪法 C1 |
| 在运行时库里实现能力、或要求库认识 `PI_*` | **一票否决** | 库宪法 C1/C6.2 事实 6 |
| 终端 / PTY、版本控制、后台常驻、开机自启 | 平台不可用（如实提示） | 规划 §8.4；宪法 A6 |

## 3. 功能需求（RFC 2119）

### 3.1 冻结能力与失败语义

- **FR-104-001** 宿主侧**必须**注册且仅注册下列八个能力名，拼写**必须**与冻结清单**逐字一致**：
  `runtime.facts`、`perm.check`、`perm.openAppInfo`、`fs.pickFiles`、`fs.pickFolder`、`shell.openExternal`、`notify.show`、`log.hilog`。
- **FR-104-002** **必须不**新增、改名、缩写、别名化任何能力名；确需新增**必须**先走库的契约变更流程（库宪法 §六.1）并同步本文件与 `plan.md`。
- **FR-104-003** 每个能力的返回值**必须**是**自描述 JSON**（含 `ok` 字段）；成功时**必须**保留库的原样透传语义（库不包装，见冻结契约 §2.7）。
- **FR-104-004** 未注册的能力名、非法入参、处理器内部异常**必须**表现为**结构化错误**（可解析 JSON，含 `error` 码），**必须不**返回空值、空数组或「假成功」。
- **FR-104-005** 任何能力的单次入参**必须**受上限约束（库默认 8 MiB，可配）；超限**必须**报错而**必须不**静默截断。
- **FR-104-006** 宿主能力的调用**必须不**承载业务数据（会话、消息、流式内容、工具进度）；违反即一票否决（宪法 A1）。

### 3.2 权限：预检与去向

- **FR-104-007** `perm.check` **必须**返回**三种**判定结果之一：`granted` / `denied` / `unknown`；**必须不**用「`false`」表达不确定。
- **FR-104-008** 当预检结果为 `denied` 或 `unknown` 时，界面侧文案**必须**同时给出：① 结论（未授权 / 不可判定）、② 原因口径、
  ③ 「去系统设置」的动作入口；**必须不**给出「可以用了」的暗示。（🔶 依据：旧壳真机实测「授予后 `checkPermission` 仍可能返回 `false`」（假阴性），因此预检意见**必须不**当作结论。）
- **FR-104-009** `perm.openAppInfo` **必须**打开**本应用**的系统设置页；失败**必须**返回结构化失败（`false`/错误码），**必须不**假装已打开。
- **FR-104-010** 需要用户授权的权限**必须**在**首屏可见之后**才申请；**必须不**在首屏出现之前阻塞等待用户操作（`FR-ARK-007`）。
- **FR-104-011** 本模块**必须不**新增权限声明项；任何权限面的改动**必须**重走「申请 → 重新生成 Profile → 装机验证」（宪法 A10）。

### 3.3 选择器（文件 / 目录）

- **FR-104-012** `fs.pickFiles` / `fs.pickFolder` **必须**使用**系统选择器**，**必须不**自绘一个「看起来像选择器」的目录浏览器来冒充。
- **FR-104-013** 选择结果**必须只回传路径**，**必须不**回传文件内容；超出「路径可用范围」的大文件**必须**走 copy（copy 到应用私有可写目录）后再回传路径。
- **FR-104-014** 用户取消选择**必须**返回结构化的「已取消」（既不是错误堆栈，也不是空路径当成功）。
- **FR-104-015** 选择到的目录**必须**能被助手**直接用作后续工具的工作目录**（`FR-ARK-037`）；路径**必须**是**绝对路径**且不依赖任何相对基准（宪法 T5）。
- **FR-104-016** 当目标位于**受系统保护的用户目录且尚未授权**时，**必须**返回「未授权 + 需要到系统设置授权并重启应用」的可读结论；
  **必须不**静默失败或伪造成功（`FR-ARK-038`）。

### 3.4 外链、导航围栏与弹窗拦截

- **FR-104-017** 外链动作**必须**在**能力已真正注册**后调用；**必须不**调用未注册的能力（⚠️ 反面教材：旧壳 `ExternalWeb.Open` 从未注册却被直接调用，
  适配器解引用空指针导致**整个应用 SIGSEGV**，🔶 旧壳 `R15` / 能力清单 #28）。
- **FR-104-018** 指向**外部站点**的链接**必须**交给系统浏览器或应用内独立承载页；**必须不**在主界面窗口内直接导航到外部站点（`FR-ARK-043`）。
- **FR-104-019** **应用自有地址**的跳转**应当**在应用内部承载（不把用户丢出应用，`FR-ARK-042`）。
- **FR-104-020** 界面发起的**新窗口**请求**必须**被拦截并按上述规则分流；**必须不**产生无内容或不可操作的新窗口（`FR-ARK-044`）。
  判定（是否主框架、目标是否自有地址）由 `103` 接线，**动作**（打开外链）由本模块提供。
- **FR-104-021** 外链动作**必须**在失败时返回结构化失败并写日志；**必须不**静默吞掉（A5）。

### 3.5 通知、系统日志、运行时事实

- **FR-104-022** `notify.show` 的通知内容**必须**不含凭据与完整会话内容（`FR-ARK-045`）。
- **FR-104-023** `log.hilog` **必须**把关键信息**同时**写入系统日志与宿主日志（双通道，宪法 T8）；任一通道失败**必须**不影响另一条通道。
- **FR-104-024** `runtime.facts` **必须**返回宿主侧可观测的运行时事实（服务状态、日志读取入口、已注册能力名清单、实际监听端口），
  且**必须**与「进程内环境事实」区分（后者由 Node 侧自检端点提供，二者不得互相替代）。
- **FR-104-025** `runtime.facts` 的返回值**必须**可用于排障：至少包含「服务是否在跑」与「日志在哪里」两项，**必须不**只返回 `ok`。

### 3.6 工作区主目录清单与窗口状态

- **FR-104-026** 应用**必须**维护一份工作区主目录清单，含**四项**：沙箱根、桌面、文档、下载；
  每项**必须**给出：绝对路径、是否存在、是否可读、授权状态（预检意见）。
- **FR-104-027** 授权状态**不可判定**时**必须**显示「不可判定」；**必须不**猜测（🔶 沿用旧壳口径：桥不可用时如实说明）。
- **FR-104-028** 清单**必须**以「助手可消费」的形式供数（环境变量 JSON，键名沿用旧壳 `PI_HOS_ROOTS`）；
  若清单缺席或非法，**必须可见地**说明「已改用兜底清单」并列出期望项（日志 + 自检输出），**必须不**静默替换成别的根、**必须不**把兜底当权威。
- **FR-104-029** 应用**必须**记住窗口**尺寸**并在下次启动时恢复（最小版）；**可以**不记位置（多显示器/2in1 形态下位置语义不确定）。
- **FR-104-030** 本模块的每一处失败**必须**在界面或系统日志中留下**可截图/可抓取**的文字（A5）。

## 4. 关键实体

### 4.1 能力实体（八条，逐条给出语义边界）

| 能力名 | 入参要点 | 出参要点 | 实现归属 | 现状 |
|---|---|---|---|---|
| `runtime.facts` | 无（可带 `keys` 过滤） | 服务状态 / 日志路径 / 已注册能力名 / 端口 | 本模块 | ⬜ 规划未实现（Phase 2） |
| `perm.check` | 权限名（或本应用的语义别名） | `granted` / `denied` / `unknown` 三态 | 本模块 | ⬜（Phase 2） |
| `perm.openAppInfo` | 无 | 是否成功到达设置页 | 本模块 | ⬜（Phase 2） |
| `fs.pickFiles` | 可选的类型过滤、是否多选 | 路径列表（**不含内容**） | 本模块 | ⬜（Phase 2） |
| `fs.pickFolder` | 可选的起始位置 | 单个目录绝对路径 | 本模块 | ⬜（Phase 2） |
| `shell.openExternal` | 绝对 URL | 是否已交系统处理 | 本模块 | ⬜（Phase 2） |
| `notify.show` | 标题 + 正文（**不得含凭据**） | 是否已发出 | 本模块 | ⬜（Phase 2，按需） |
| `log.hilog` | 级别 + 文本 + 关联标识 | 是否已写系统日志 | 本模块 | ⬜（Phase 2） |

### 4.2 数据实体

| 实体 | 字段（语义） | 生命期 | 现状 |
|---|---|---|---|
| 工作区主目录记录 | `id`（`sandbox`/`desktop`/`documents`/`download`）、`label`、`path`、权限别名（沙箱项为空） | 每次启动生成；供助手读取 | ⬜（Phase 2） |
| 窗口状态偏好记录 | 尺寸（宽/高）；保留字段：位置 | 跨启动持久 | ⬜（Phase 2） |
| 权限判定 | 结论（三态） + 权限名 + 时间 | 单次调用 | ⬜（Phase 2） |
| 能力调用结果 | `ok` + 负载或 `error` 码 + 能力名 | 单次调用 | ⬜（Phase 2） |

## 5. 验收场景（Given / When / Then，逐条可证伪）

| 编号 | Given | When | Then（观测点） |
|---|---|---|---|
| `AC-104-01` | 八个能力已注册、服务在跑 | 请求 `runtime.facts` | 返回可解析 JSON 且含「是否在跑」与「日志路径」；**含全部八个已注册能力名**（同一份 JSON 可截图/可 `curl`） |
| `AC-104-02` | 权限未授予 | 请求 `perm.check` | 返回 `denied`（不是空值、不是 `ok:true`）；文案含「去系统设置」 |
| `AC-104-03` | 权限已授予且目录确实可读 | 请求 `perm.check` | 返回 `granted` **或** `unknown`；**不得**把「预检意见」写成「已授权可用」的结论（对照真实读写结果） |
| `AC-104-04` | 应用处于前台 | 请求 `perm.openAppInfo` | 系统设置页**真的**出现在截图中；返回 `ok:true` |
| `AC-104-05` | 用户选择了目录 A 并确认 | 助手以 A 为工作目录读写一个中文名文件 | 工具调用成功；返回的路径可**直接**用于后续调用（截图 + 工具输出） |
| `AC-104-06` | 选择器被打开 | 用户取消 | 返回结构化「已取消」；界面**没有**出现错误堆栈，**没有**伪造成功 |
| `AC-104-07` | 目标目录未授权 | 请求在该目录写入 | 返回「未授权」结论；操作日志中**不出现**「保存成功」 |
| `AC-104-08` | 主界面在本地服务页 | 点击一个外部站点链接 | 主界面**没有**被导航走（前后截图对比）；外链由系统浏览器或应用内承载页承接；无 SIGSEGV（`hilog` 无崩溃） |
| `AC-104-09` | 主界面在本地服务页 | 触发一次新窗口请求 | **没有**产生无内容/不可操作窗口；请求按分流规则处理 |
| `AC-104-10` | 工作区清单已生成 | 请求清单（或跑助手侧 `/roots` 自检） | 四项主目录各自给出路径 + 状态 + 授权；桥不可用时显示「不可判定」而不是猜测 |
| `AC-104-11` | 窗口被调整为某尺寸 | 重启应用 | 窗口尺寸与调整后一致（两次截图对比） |
| `AC-104-12` | 任意失败面（外链失败 / 通知失败 / 选择器失败） | 观察 | 界面或系统日志中有**可截图/可抓取**的文字；**没有**静默吞掉 |
| `AC-104-13` | 服务侧对**未注册**的名字发起调用 | 观察返回值 | 得到含 `unregistered` 的**结构化错误**；应用**没有**崩溃 |
| `AC-104-14` | 服务侧发来超上限的入参 | 观察返回值 | 得到含 `payload-too-large` 的**结构化错误**；**没有**截断后继续 |

> **禁止的判据**（与宪法 A7 同源）：用 `uitest dumpLayout` 的返回内容判「界面上出现了 X」；用「点了一下看起来生效了」判能力可用；
> 用「日志里出现了某一行」判执行；用「重试后成功」掩盖首次失败。每条判据**必须**能由第三方用截图 / 可解析 JSON 复现。

## 6. 非功能需求

| 编号 | 项 | 要求（可验证） |
|---|---|---|
| `NFR-104-001` | 主线程不阻塞 | 选择器与通知**必须**异步；等待用户操作期间**必须不**阻塞界面渲染（流式回复不中断） |
| `NFR-104-002` | 调用上限 | 单次入参 ≤ 8 MiB；单次调用**必须**有超时上限，超时**必须**返回结构化错误 |
| `NFR-104-003` | 幂等与可重入 | 纯查询能力（`runtime.facts`/`perm.check`）**必须**可重复调用且无副作用；注册**必须**幂等（同名覆盖） |
| `NFR-104-004` | 可观测 | 每次能力调用**必须**留下调用计数与错误计数（供 `runtime.facts` 与诊断面板读取） |
| `NFR-104-005` | 安全 | 通知与日志**必须不**含凭据；外链**必须**只接受绝对 URL，**必须不**接受 `javascript:` 等可执行协议 |
| `NFR-104-006` | 路径纪律 | 回传路径**必须**绝对；**必须不**依赖 `process.cwd()` 语义（真机 = `/`，宪法 T5） |
| `NFR-104-007` | 权限纪律 | 本模块**必须不**新增权限声明；新增**必须**重走 Profile 复验（A10） |
| `NFR-104-008` | 体积 | 本模块**必须不**引入新的原生件（不改包内原生库清单） |
