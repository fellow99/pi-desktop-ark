## 1. 模块概述

### 1.1 目的

把「**受管运行时 + 本地服务**」接入应用，并使整条启动路径**可观测、可失败、可判定**：

1. **依赖接线**：以**预构建产物**消费运行时提供方（✅ 跨工程源码相对导入被构建器拒绝 `00309001`，宪法 T7）；
2. **运行时投放委托**：应用侧只做转发，真正投放由提供方**唯一一份**实现完成（幂等 + 校验门禁）；
3. **三段式启动编排**：①准备入口（物化/定位载荷）→ ②**投递**启动 → ③**就绪探活**；
4. **状态机**：壳侧可用性状态与运行时状态并列存在、互相映射，不混为一个；
5. **端口与单实例**：端口随机/先探测空闲，应用单实例（硬约束 ⑰，详见 §7）；
6. **关停与日志读回**：关停有超时上限且不假装能停；日志**谁写谁读**。

### 1.2 解决的问题

| 问题 | 不解决的后果 |
|---|---|
| 界面**什么时候可用**没有依据 | 白屏、静默重试、把「已投递」当成「已就绪」（✅ 现状：投递语义只代表已交后台线程） |
| 固定端口被占用 | ✅ **实测**：端口冲突 ⇒ 载荷未捕获异常 ⇒ **整个应用进程 abort**（`Cpp Crash`，崩溃栈含引导件） |
| 多实例 | 两个实例互抢端口与数据目录（⑰） |
| 失败只进日志 | 用户拿到的是「应用消失了」而不是可截图的失败态（A5） |
| 崩溃被当成可恢复 | 进程内运行时**没有重启路径**（硬约束 ⑥）；暗示可恢复 = 误导（C5） |
| 日志只写不读 | 「写成功」无法证伪（T8 / 库宪法 C3） |

| 含 | 不含（归属） |

## 3. 功能需求

### 3.1 依赖接线与投放（FR-101-001 ~ FR-101-003）

- **FR-101-001** 运行时提供方**必须**以**预构建产物**形式接入应用构建链；**必须不**依赖跨工程的源码相对导入（✅ 该形态被构建器拒绝 `00309001`）。
- **FR-101-002** 运行时与其产物**必须**经由 ohpm 中心仓包获取（`@fellow99/node-bridge` + `@fellow99/node-runtime`，版本锁定）；分发由包管理链**唯一**完成，应用侧**必须不**自建第二份获取/投放逻辑（历史的手工投放脚本已退役）；依赖的安装**必须**幂等（重复执行结果一致）。
- **FR-101-003** 投放**必须**在写入前做**摘要 + 属性门禁**校验；任一不通过**必须**硬失败并给出可读原因与补救路径；**必须不**静默继续（✅ 门禁已达成：锁文件 SHA 与 HAP 内产物一致）。

### 3.2 启动编排（FR-101-004 ~ FR-101-007）

- **FR-101-004** 启动**必须**分三段执行且**必须**分阶段可观测：①准备入口（把只读载荷物化/定位为运行时可达的位置）→ ②投递启动 → ③就绪探活。
- **FR-101-005** 「投递成功」**必须**只解释为「已交给后台执行」，**必须不**作为「可用」依据。
- **FR-101-006** 「就绪」判定**必须**基于**对本地服务的真实请求返回成功**；**必须不**以进程存在性、日志出现某行、或「启动动作已发起」作为判据。
- **FR-101-007** 就绪等待**应**采用退避/重试；重试次数与间隔**必须**是**可见常量**（可被测试引用）；到达上限**必须**立即转入失败态，**必须不**无限等待。

### 3.3 端口与单实例（FR-101-008 ~ FR-101-010）

- **FR-101-008** 本地服务监听端口**必须**随机或**先探测空闲**后使用；**必须不**依赖某固定端口一定可用（⚠️ 固定端口的后果是整进程 abort，见 §7）。
- **FR-101-009** 实际监听端口**必须**由**服务侧回传**（文件或宿主桥）；宿主**必须不**猜测端口。
- **FR-101-010** 应用**必须**保证**单实例**语义：再次启动**必须**不产生第二个独立实例（否则互抢端口与数据目录）。

### 3.4 失败可见与崩溃终态（FR-101-011 ~ FR-101-015）

- **FR-101-011** 投递失败、探活超时、（未来的）崩溃**必须**呈现为**可见失败态**，且**必须**同时给出：**失败阶段**、**可读原因**、**下一步动作**（重试 / 查看日志 / 重启应用）。
- **FR-101-012** 「崩溃」**必须**是**终态**：**必须不**实现自动重启，**必须不**在文案或行为上暗示可以自动恢复。
- **FR-101-013** 系统请求终止应用时**必须**触发关停流程（尽量停止监听与写入）；关停**必须**有**超时上限**，超时后**必须**直接结束；若运行时**本就没有**优雅停止路径，**必须**如实记录该限制，**必须不**伪造「已优雅停止」。
- **FR-101-014** 宿主**必须**持有**日志读回**通道：至少能读回**日志尾部**与**崩溃记录**（字段非空）；读回失败**必须**返回占位文本而**必须不**抛异常。
- **FR-101-015** 载荷**必须**自装**未捕获异常**与**未处理拒绝**兜底，并写入**独立于标准输出**的结构化日志；**必须不**只依赖标准输出（⚠️ 实测：原生层会把渲染组件的本地输出混进同一份日志）。

### 3.5 时序、环境与观测（FR-101-016 ~ FR-101-020）

- **FR-101-016** 应用语义环境变量（数据根、离线开关、代理绕过、监听策略等）**必须**由本工程设置，且每项**必须**只有**一处**落点；**必须不**出现「某个环节顺手设一下」。
- **FR-101-017** 启动**必须**先让首屏可见（应用内加载页），**之后**才投递运行时与申请运行期权限；**必须不**在首屏出现前阻塞等待用户操作（⚠️ 权限弹窗会卡住启动屏 → `APP_INPUT_BLOCK`）。
- **FR-101-018** 关键阶段**必须**同时写**系统日志**与**界面文本**（双通道）；系统日志**必须**带固定域/标签以便一条命令抓全链。
- **FR-101-019** 就绪后再次收到启动请求**必须**幂等：返回已有地址并**必须不**重复投递。
- **FR-101-020** 运行时状态**必须**可查询（壳侧状态 + 提供方状态 + 原生阶段 + 最近失败原因），供诊断面板与测试断言使用。

## 5. 验收场景（Given / When / Then）

> 每条都可证伪；「看哪里」已写在 Then 里（宪法 A7）。

- **AC-101-01 阶段推进可见**：Given 冷启动；When 应用启动并最终就绪；Then **至少出现 2 个不同的阶段文本**（截图 ≥2 张、文本不同），且系统日志有对应行。
- **AC-101-02 就绪判据来自真实请求**：Given 服务已起；When 探活目标端点返回 200；Then 状态变为就绪**且**该端点确为服务真实存在路径；反例：把探活目标改成一个服务不提供的路径时**不得**出现就绪状态。
- **AC-101-03 探活上限后立刻失败**：Given 目标端口无人监听；When 启动；Then 在**上限时间**（次数 × 间隔，含容差）内出现失败态，且文案**含尝试次数、间隔、日志路径**。
- **AC-101-04 端口被占用仍能起**：Given 固定端口被其它应用占用；When 启动本应用；Then 应用仍能到就绪，**实际端口不等于**被占端口，且**端口回传记录**与服务自报端口一致（截图 + HTTP 字段互证）。
- **AC-101-05 单实例**：Given 应用已在运行；When 再次启动同一应用；Then 只有一个实例（列表命令只出现一条），且不产生第二个窗口。
- **AC-101-06 投递失败可见**：Given 入口路径被注入为不存在；When 启动；Then 出现失败态，文案含提供方返回的 `message`（原文可读）。
- **AC-101-07 崩溃是终态**：Given 载荷被注入一次致命错误；When 应用重启后观察；Then 界面呈现终态失败 + 「请重启应用」，**不出现**自动重启/自动恢复行为。
- **AC-101-08 日志可读回**：Given 应用已运行；When 打开诊断入口；Then 出现**非空**日志文本且含至少一行服务侧输出（截图，文本长度 > 0）。
- **AC-101-09 崩溃记录可读回**：Given 发生过一次载荷崩溃；When 重启后打开诊断入口；Then 崩溃记录字段（时间戳 / 信号 / 阶段）**非空**（截图或端点原文）。
- **AC-101-10 关停有上限**：Given 应用运行中；When 关闭窗口/系统请求终止；Then 日志出现关停流程记录，且退出耗时**不超过**超时上限；随后再次启动**能到就绪**。
- **AC-101-11 幂等**：Given 已就绪；When 再次触发启动；Then 返回已有地址，且**不产生**第二次投递（提供方状态不变、日志无第二次投递记录）。
- **AC-101-12 环境契约生效**：Given 应用运行中；When 读取诊断输出；Then 应用语义变量为期望值，且沙箱根与临时目录落在应用私有可写目录。
- **AC-101-13 载荷兜底生效**：Given 载荷内被注入一次未捕获异常；When 观察进程与日志；Then 应用进程**仍存活**，且载荷的独立日志文件出现该异常的记录。

## 7. 假设与约束

1. **运行时是单次启动的**：进程内运行时每进程只能启动一次；**崩溃是终态**，不存在进程内重启路径（硬约束 ⑥）⇒ 失败态 UX 只允许「读日志 / 读崩溃记录 / 重启应用」（宪法 A5）。
2. **端口冲突会带走整个应用进程**：✅ 实测链路「端口被占 ⇒ 载荷 `EADDRINUSE` ⇒ 未捕获异常 ⇒ 应用进程 abort」⇒ 随机端口 + 单实例是**硬约束**（⑰），不是优化项。
3. **运行时结论以提供方文档为准**（宪法 A3）：`dlopen` 裸名、线程与栈、JIT↔ACL↔WASM 链条、子进程语义等**一律引用**，本模块只写「依赖了哪一条 + 怎么验」。
4. **授权面是刚性前置**：缺少受限授权则空转即崩（SIGTRAP），开放权限不可替代；授权面变更**必须**重走「申请 → 重新生成授权配置 → 装机验证」（宪法 A10）。
5. **载荷形态决定首启代价**（模块 102）：只读直读为零解压；若走归档自解包路线，**必须**有阶段文本与可重试语义。
6. **渲染侧的 loopback 可达性尚未验证**（🔶 同形态先例在售；本工程 ⬜ P0-3）⇒ 就绪后的渲染入口在模块 103 收口；本模块只负责「服务确实活着」。
7. **日志通道的已知缺陷**：原生层把标准输出重定向到文件时会把渲染组件的本地输出一并写入（⚠️ ✅ 实测）⇒ 载荷必须另写结构化日志（⑱），本模块负责**读回**。
8. **不得绕开平台代码签名/可执行内存控制**（合规红线 G11）：本模块不引入任何绕行组件。
