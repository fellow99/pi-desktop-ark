## 1. 目的

鸿蒙环境**没有 `git`**，`git` 全部命令不可用。本设计交付一个 **pi agent 扩展** `harmony-git`，把**纯 JS 的 isomorphic-git 1.44.2** 嵌入应用，向模型注册 **21 个 `git_*` 工具** + 1 个凭据管理工具 `git_credentials`，并提供**设备自管的 git 原生凭据文件**管理带账号仓库凭据。全部操作在应用**自己进程**内的 Node（node-bridge 托管，非子进程）里完成，不依赖外部二进制、不需要子进程、不联网安装（`PI_OFFLINE=1`），**不触碰父工程**。

**范围外（明确不做）**：`rebase`、`blame`、`grep`（已有 `grep` 工具）、SSH 传输、SHA-256 仓库。`git@host:` 自动改 https。

## 2. 现状与差异（相对 pi-desktop-hos）

`harmony-git` 扩展**与 hos 工程共享同一份代码**（hos 为单一事实源，见 §6.3）；两侧只是**落点目录、Node 版本、装配/物化脚本、权限桥**不同：

| 关注点 | pi-desktop-hos（事实源） | **pi-desktop-ark（本工程）** |
|---|---|---|
| 运行时 | Electron-on-鸿蒙 37.2.3，进程内 **Node 22.17.0** | 无 Electron；node-bridge `dlopen libnode.so` + `node::Start`，**Node v24.2.0** |
| 包名 / 应用 | （electron module） | `org.fellow99.pi.PiDesktopArk` / "Pi Desktop V2" |
| 扩展落点（源） | `extensions/harmony-git/` | **`payload/extensions/harmony-git/`** |
| 装配 | 五步链（`collect-pi.mjs` 已递归复制 extensions） | `scripts/assemble-payload.mjs`（`APP_PAYLOAD_ENTRIES` 含 `extensions`，递归 tree-walk）→ `pi-web.tar.gz` 入 `entry/.../resfile/pi-web/` |
| 运行期物化 | `main.js#materializeBundledResources` cpSync → `<userData>/pi-agent/extensions/` | `pi-web-launch.js#materializeAgentResources`（:601-694，原子 tmp+rename）→ `<filesDir>/pi-agent/extensions/` |
| 设备上扩展最终路径 | `<userData>/pi-agent/extensions/harmony-git/` | **`<filesDir>/payload/<sha12>/pi-web/extensions/harmony-git/` → copy → `<filesDir>/pi-agent/extensions/harmony-git/`** |
| 权限桥 | `globalThis.__PI_HOS_PERMISSION__`（可用，两动作） | **Phase 1 桥传输未接线**：扩展读不到即如实报「不可判定」，不猜 |
| 环境契约 | `src-main/main.js#assembleSandboxEnv` | `payload/env.js#buildEnv`（唯一事实源）+ `pi-web-launch.js` |
| 凭据文件路径 | `<userData>/pi-agent/.git-credentials` | `<filesDir>/pi-agent/.git-credentials`（同为 `$PI_CODING_AGENT_DIR`） |

**与 hos 一致的关键事实（共享，详见 hos 文档 §2/§3）**：pi 扩展契约（jiti + `pi.registerTool` + 普通 JSON-schema + `{content,details,isError}`）、`PI_OFFLINE=1`、设备无 git/npm 不可用、出网 HTTPS 可用、扩展须自包含只用 `node:` 内置、无 dsh 式逐写审批（唯一门禁 project trust）、isomorphic-git 单文件 bundle（esbuild，含 `diff@9`，888 KB，`node:*` external）**本机 Node v24 + jiti 2.7.0 实测可加载并跑通真仓库操作**。

> **本工程 Node 是 v24**（与 hos 的 22 不同）：bundle 经 `--platform=node` 构建、`node:*` 外置，v22/v24 均可用（本机 v24 已实测）。`harmony-exec.js` 等现有扩展已证明纯 `node:` 代码在两工程间可"原样搬"。

## 3. 方案要点（与 hos 同源，此处摘要）

- **依赖供给（D3）**：构建期 esbuild 预打**单文件 CJS bundle**（isomorphic-git + `diff@9` 合并，`node:*` external），**提交入库**，置扩展 `vendor/isomorphic-git.bundle.cjs`。jsdiff 并入 bundle（D4）。不做 vendored node_modules、不做运行时安装。
- **工具粒度（D1/D2）**：一动词一工具，21 个 `git_*` + 1 个 `git_credentials`；网络操作全做，凭据**设备自管** `$PI_CODING_AGENT_DIR/.git-credentials`（git 原生格式，0600，原子写，脱敏 list），`auth.js` 经 `onAuth` 注入。
- **围栏（D6）**：仓库根 chroot（防 `..` 逃逸/绝对路径/根外软链）+ `PI_HOS_ROOTS` 合理性提示；**不做**逐写审批；fs 适配器**全方法 `async`**（isomorphic-git `isPromiseFs()` 方言契约，复刻 dsh 真机发现，防永久挂起）。
- **自建缺口**：`diff`（bundle createTwoFilesPatch）、`show`、`revert`（fail-closed）—— 与 hos 完全一致。

## 4. 代码组织与 ark 侧装配

### 4.1 单一事实源 + 同步

`extensions` 源在 **`pi-desktop-hos/extensions/harmony-git/`**（hos 是 ark 的上游产物来源：ark `assemble-payload.mjs` 默认 `--from ../pi-desktop-hos/pi-dist`）。新增**幂等同步脚本**：

- `scripts/sync-git-extension.mjs`：把 hos 的 `extensions/harmony-git/**`（index.js、lib/、vendor/、package.json、tests/、README）拷贝到 **`payload/extensions/harmony-git/`**，在 ark 副本头部加「V2 差异」注记（沿用现有 4 扩展"原样搬 + 头部注记"约定：`harmony-exec.js`/`harmony-runtime.js`/`harmony-search.js`/`harmony-workspace-roots.js` 在 ark 均带 V2 头注）。

> 与现有扩展不同：现有 4 个是**逐文件**手工同步；本扩展是**整目录**，用脚本同步以保证 lib/、vendor/ 多文件一致、可重复。

### 4.2 装配链（无需改 assemble 脚本）

```
hos 源：pi-desktop-hos/extensions/harmony-git/**          ← 单一事实源
   │  sync-git-extension.mjs（幂等拷贝 + V2 头注）
   ▼
ark：payload/extensions/harmony-git/**                    ← 入 git
   │  assemble-payload.mjs（APP_PAYLOAD_ENTRIES 含 'extensions'，walkTree 递归）
   ▼
build/payload-stage/pi-web/extensions/harmony-git/**
   │  tar → entry/src/main/resources/resfile/pi-web/pi-web.tar.gz + pi-web.version
   ▼
hvigor assembleHap → entry-default-signed.hap
   ▼ 运行期
bootstrap.js 解包 → <filesDir>/payload/<sha12>/pi-web/extensions/harmony-git/**
   │  pi-web-launch.js#materializeAgentResources（copy extensions/**）
   ▼
<filesDir>/pi-agent/extensions/harmony-git/**            ← pi 自动扫描
   │  jiti.import(index.js) → 工厂注册 21+1 工具
```

**无需改 `assemble-payload.mjs`**（`extensions` 已在 `APP_PAYLOAD_ENTRIES` 且递归拷贝）；**无需改 `pi-web-launch.js`**（`materializeAgentResources` 已递归 copy `extensions/**`）。目录扩展整树（含 `vendor/*.bundle.cjs`）随 `extensions/` 一并物化到 `<filesDir>/pi-agent/extensions/harmony-git/`，pi 发现其子目录 `index.js` 并 jiti 加载。

### 4.3 凭据文件（ark 路径）

`$PI_CODING_AGENT_DIR/.git-credentials` = `<filesDir>/pi-agent/.git-credentials`（`payload/env.js` 设 `PI_CODING_AGENT_DIR=<HOME>/pi-agent`）。格式/权限/匹配/写入规则与 hos 完全一致（git 原生 URL 一行一条，`0600`，临时文件+rename 原子写，容忍注释，前缀+后者覆盖）。

## 7. 错误处理、验收标准、操作清单、限制、风险、提交约定

与 `pi-desktop-hos/docs/204-插件-GIT.md` §12–§18 **完全一致**（领域逻辑共享），此处不重复。要点：
- 错误如实归因（非仓库/缺凭据/认证被拒/冲突/越界/网络失败/non-fast-forward/取消），不假装成功、不静默重试、不自动 force。
- `rebase` 明确报「本平台不支持」；`revert` 分叉 fail-closed。
- 凭据明文不进对话/details/日志；`git_credentials` list 脱敏。
- 提交用 Conventional Commits 前缀（git-commit 技能），main 分支不新建/切换，不加 AI 署名。
